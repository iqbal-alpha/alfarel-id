# Taste Skill Frontend Rules

This workspace utilizes **Taste Skill** (The Anti-Slop Frontend Framework) to deliver world-class, premium user interfaces.

## Core Rules

1. **Perform a "Design Read" Before Generating UI**:
   - Before writing frontend code, state in one line:
     `Reading this as: <page kind> for <audience>, with a <vibe> language, leaning toward <design system or aesthetic family>.`
   - Read signals from the brief: page kind, vibe keywords, audience expectations, brand identity, and quiet constraints.

2. **Reject Generic LLM Aesthetics ("Anti-Slop")**:
   - Avoid generic AI defaults: AI-purple gradients, generic centered hero over purple mesh, repetitive three-card feature rows, generic glassmorphism slapped on everything, and default Inter/Roboto sans-serif without character.
   - Choose curated typography (from Google Fonts or system fonts tailored to the aesthetic).
   - Use high-contrast hierarchy, deliberate whitespace, and refined micro-interactions.

3. **Available Aesthetic & Workflow Skills**:
   - `taste-skill`: General anti-slop frontend framework and design read discipline.
   - `minimalist-skill`: Restrained, typography-driven, elegant minimalism.
   - `brutalist-skill`: Bold typography, raw borders, high contrast, neo-brutalist style.
   - `soft-skill`: Soft shadows, tactile elements, warm rounded aesthetics.
   - `brandkit`: Cohesive color palettes, typography scales, and token systems.
   - `image-to-code-skill`: Translating design mockups and screenshots into production code.
   - `stitch-skill`: Stitching visual components into a unified interface.
